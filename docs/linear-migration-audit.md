# Linear migration audit

The inventory, findings and plan for moving every visible part of F1 Apex Data onto one Linear design system
([linear-design-spec.md](linear-design-spec.md)). The measured section at the end is generated by
`node scripts/audit-linear.mjs && node scripts/linear-audit-report.mjs` and compared with the baseline recorded before migration
(`docs/linear-audit-baseline.json`).

**What the audit checks.** Every route and state below, in dark and light, at 1440, 1024 and 390 px:
(1) rule checks per element against the spec (type scale, weights, text colours, radii, control heights, gradients, glows,
uppercase); (2) component families: every distinct look of a card, button, heading and table header, to expose competing
implementations even when each value is individually on the scale; (3) layout fidelity at desktop width: rail width, rail row
heights, header height, the number of distinct left edges content uses, the gaps between stacked blocks, cards nested in cards,
row heights, and the heading size sequence; (4) screenshots of each route compared by eye with the reference captures. Passing
(1)–(3) does not mean a page matches Linear: (4) decides.

**Reference status.** The signed-in Linear app was measured on 2026-11-10 (dark theme); its values are marked [A] in the spec and
win over the marketing replica [M]. The tables in §2 below were written against the replica before that; where they disagree
with the spec (weights 510/590, 240 px rail, transparent cards), the spec is right. The light theme still uses published [P] values.

## 3. Plan

**One authority, no new layer.** `skins.css` becomes the single Linear system, rewritten in this order with no version sections:
tokens · frame · rail · header and view bar · primitives (nav row, icon button, select, primary, small, segmented, tile, chip,
card, floating, heading roles, table, list row, input) · page compositions (session, car performance, season) · responsive.
`season.css` keeps only Season-specific layout; its appearance rules move to the primitives. As each section is rewritten, the
v3–v5 rules it replaces are deleted, and appearance rules for the same components in `apple-ui.css`, `macos-ui.css`,
`macos-window.css`, `design-system.css`, `polish.css`, `hig-system.css` and `ui-controls.css` are deleted once a screenshot
check shows the replacement renders as intended. Layout rules in those files (grids, sizing) are kept unless superseded.

**Order.**
1. Tokens and frame (everything depends on them).
2. Representative page: **Season · Standings** (frame, rail, header, tabs, table, cards, charts, segmented control). Migrate it
   completely, verify by screenshot against the reference in both themes and three widths, and only then continue.
3. Remaining Season tabs, then Car performance (largest nesting problem), then Session analysis (densest page), then the lap
   sheet, menus, tooltips and the catalogue.
4. After each route: rerun the audit and the report, screenshot, fix, repeat.

**Safeguards (Phase 7).**
- A test that fails if any stylesheet contains version banners (`v3`, `v4`, `v5`) or a second definition of a primitive's
  appearance outside `skins.css` (CSS ownership map: primitive classes × appearance properties → owning file).
- A test that fails on gradients, glows (blurred shadows on non-floating elements), uppercase text and off-scale sizes in the
  shipped CSS, with a short allow-list for data visualisation.
- The audit runs in the browser test suite for the representative routes and fails when a component family exceeds its target.
- `AGENTS.md` and `CLAUDE.md`: mandatory rules for agents (use primitives, no new layers or version sections, verify by
  screenshot).

### Removing superseded rules safely

`node scripts/legacy-overrides.mjs` renders every state in both themes and at three widths, removes the appearance declarations
of the Apple/macOS stylesheets in the live page, and puts back each one whose removal changes any element's computed style,
repeating until nothing differs. `node scripts/prune-legacy.mjs` then deletes from the source files only what was never put
back. After a prune, compare screenshots (`audit-linear.mjs --shots`) before and after: they must be identical.
