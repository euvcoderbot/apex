## Fixed

| Issue | Change |
| --- | --- |
| Unnecessary “Other links” controls | Removed the whole disclosure and its obsolete CSS. Genuine corners/straights remain; automatic links between selected adjacent corners still work. |
| Conflicting pill sizes | Category tabs, segmented filters, corner buttons and refresh actions now resolve to the same 30 px height and 14 px text in fine-pointer layouts. The existing touch-height token remains 44 px. Multi-line lap/driver choices deliberately remain content-sized. |
| Wrapped corner labels | Corner choices have content-aware width and no-wrap labels rather than a fixed width that can split longer labels. |
| Misleading warnings on unrelated charts | The shared bar renderer now uses a trace-specific flag. A generic `provisional` field cannot produce a “source gaps” tooltip on results/points charts. |
| Unequal corner driver rows | Moved the former entry/exit correction model into a closed, explicitly labelled diagnostic. Primary numeric cells use the units in their column headers instead of repeating them in each value, saving narrow-panel space. The diagnostic no longer makes one row taller or implies it is the current season estimator. No scientific calculation was changed. |
| Oversized map | Replaced the fixed 320 px canvas height with a bounded viewport-relative height. Trace and map regions remain simultaneously present. |
| Floating refresh on narrow screens | Headers without subject filters keep refresh alongside the title/count instead of on an otherwise empty third row. Narrow titles use the compact title token. |
| Ambiguous staged session selection | Lap telemetry now identifies the actually loaded year, event and session, independent of selector changes awaiting “Load session.” |
| Confirmed dead declarations | Removed `enhancedTraceMode` and `trendChartMode`; the conservative shared-script audit reports no remaining top-level candidates. This is not proof that every legacy CSS rule is removable. |

## Outstanding issue and follow-up improvements

1. **Abu Dhabi 2025 corner metadata — fixed (22 October 2026).** Cause: with the F1
   timing archive down, `/api/session` takes the OpenF1 alternate path, and that
   path never attached circuit info, so the comparison correctly withheld corner
   controls. `server.py` now attaches the same-venue corner positions there
   (`get_fallback_circuit_corners`, matched by the payload's own location, never
   another track). Abu Dhabi 2025 returns the 16 official turns (Yas Marina's
   layout is unchanged since 2021), and VER/NOR T1 now compares. No marker
   positions are invented and no rejection check was weakened. Regression test:
   `test_alternate_session_gets_same_venue_corners_but_never_another_track`.
2. **Figma synchronization:** update the existing editable component/screens once
   its tool allowance is available. Do not describe this release as Figma-synced.
3. **Long-term CSS simplification:** the legacy layers remain behind the final
   window/component layer. A future removal pass should use visual coverage by
   state; deleting rules merely because another selector currently wins is unsafe.
4. **Keyboard/touch/assistive-technology depth:** automated semantics and keyboard
   unit tests pass, but manual screen-reader and real touch-device checks remain
   useful. Dense evidence tables should retain their own scrollable region.

The corner-panel “Modelled entry / exit diagnostic” was reworded: it applies the
same entry-speed correction and exit-speed credit as the season cornering metric,
so it is no longer described as separate from it.

Not completable from code: item 2 needs the Figma plan allowance; item 4 needs
people with a screen reader and a physical touch device; item 3 is deliberately
left as a visual-coverage task rather than deleting rules that merely lose today.

Regression coverage adds removal, control-token sizing, diagnostic isolation,
loaded-session context and warning-scope tests. Python measurements are
unchanged by the interface release; the Abu Dhabi fix changes only the session API.
